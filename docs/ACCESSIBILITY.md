# Accessibility (WCAG 2.1 AA)

Audit of 2026-11-17. Covered: the map viewer, search, walking directions, the editor, sign-in, the home page and the marketing site, in all three themes (classic, night, signage), on desktop and on a phone. Method: an automated axe-core scan of every screen and state, contrast math on every theme color pair, and a keyboard and screen reader pass by hand.

## Fixed

| Area | Problem | WCAG | Fix |
|---|---|---|---|
| All dialogs | Tab could leave the dialog into the page behind it; focus was lost when it closed; a dialog re-ran its setup on every parent re-render, throwing focus back to the first field while typing | 2.4.3, 2.1.2 | Tab stays inside, focus returns to the button that opened it, setup runs once, title linked with `aria-labelledby` |
| Focus ring | Light blue ring (1.8:1 on white, 1.6:1 on signage beige) was hard to see; search boxes showed no ring at all | 2.4.7, 1.4.11 | Ring color per theme (blue, darker blue, yellow), at least 3.8:1 on every background; white on the navy signage header; search boxes show the ring around the box |
| Floor buttons | The selected floor's text was too faint on some floor colors: dark on purple 1.9:1 in night, white on orange 3.7:1 in signage | 1.4.3 | Text is white or near-black, whichever reads better on that floor's color (4.5:1 or more on all 8) |
| Editor floor tabs | Floors could not be reached with Tab at all; the options button was nested inside the tab | 2.1.1, 4.1.2 | Each floor is a real button; the options menu takes focus, arrow keys move through it, Escape closes it and returns focus |
| Editor sidebar | Hide-sidebar button sat inside the tab list | 4.1.2 | Moved out of the tab list |
| Viewer | Map drawing had no text alternative; no page heading or landmarks | 1.1.1, 1.3.1 | Map labelled as an image pointing to search; map name is the page heading; search is a search landmark |
| Viewer search | Result count wasn't read out; no keyboard way into the results; picking a result dropped focus to the page | 4.1.3, 2.1.1, 2.4.3 | Results count, the selected place, the start question and the route summary are read out by screen readers; Down arrow enters the list, Escape goes back; focus moves to the place's card |
| Directions | Pressing Directions, picking a start or closing dropped focus to the page | 2.4.3 | Focus moves into the directions panel, and back to the Directions button on close |
| Phones | Back, Refresh, Share and Close buttons in the viewer were 32px | 2.5.5 (AAA, best practice) | 44px on touch screens; floor buttons and panel buttons at least 44px tall |
| Home | Empty slot buttons were named differently from what they show | 2.5.3 | The name now starts with the visible text |

The marketing site and sign-in page passed the automated scan and the keyboard pass with no changes needed (page landmarks, visible focus, reduced motion respected, form errors announced).

`e2e/accessibility.spec.ts` guards these: keyboard search, directions focus, floor contrast in all themes, editor floor tabs and menu, and dialog focus.

## Follow-ups done (2026-11-18)

- **Field borders** use a new `--field-border` color, at least 3:1 against the panel in every theme (WCAG 1.4.11). Button borders are unchanged.
- **Map highlight ring** has a thin dark edge around the yellow ring, so it stands out on the light map backgrounds.
- **Floor list view**: the list button in the viewer header shows every place and every row of spaces on the floor as text; picking one shows it on the map. Built by `floorListing()` in `src/model/listing.ts`.
- **Editor without a mouse**: the Layers list is reachable with Tab, arrows move through it and Enter selects. The keyboard shortcuts dialog (?) has a "Without a mouse" section. Freehand drawing still needs a pointer.
- **Accessibility statement** at bergeronmaps.com/accessibility/, linked from every page footer (generated by `scripts/site-pages.mjs`).

## Screen reader pass (2026-11-19)

A real screen reader this time: Orca 46 (the GNOME screen reader) on Chromium, driven by real key presses, with every word it spoke logged. Covered: the viewer (page structure, search, the place card, directions, the floor list, floor buttons), online sign-in, and bergeronmaps.com (home page, hero demo, product demo, contact form, the savings calculator on the industry pages). The scripts are in `scripts/orca/` and can be run again.

Most of it already read well: one page heading per screen, named landmarks (search, Floors, main), buttons with clear names, floor buttons read as pressed or not pressed, the floor list read as headed groups, focus moving into the directions panel and back, and form errors read out on the marketing site.

### Fixed

| Area | What Orca said (or didn't) | Fix |
|---|---|---|
| Viewer: closing the place card | Escape or Close: silence, focus dropped to the page | Focus goes to the search box (without popping the old results open) |
| Viewer: floor buttons | Only "pressed"; nothing said the map changed | "Floor 2 shown." (and "with the route" during directions); route steps that change floor say it too |
| Viewer: search with a card open | Typing read the card again, not the result count | The count is read while searching |
| Viewer: typing a search | "No matches" after the first letter was cut off by the next key press, so nothing was heard | The count is read once typing pauses (0.6 s) |
| Viewer: lots of results | "30 results" when there were more | "30 results shown. Type more to narrow them down." |
| Directions | "about 1 minutes, 1 steps" | "about 1 minute, 1 step" |
| Sign-in: sent | Silence after "Email me a sign-in link": the button was gone and focus with it | Focus moves to the "Check your email" panel, which reads its message |
| Sign-in: wrong email | The browser's own bubble for some typos, the app's message for others; the field wasn't tied to the message | The app's message every time, linked to the field (`aria-invalid`, `aria-describedby`) |
| Site: hero phone and product demo | While playing on their own they announced every search ("1C12", "Key box", "EV charger 1"…) and every step, talking over whatever the visitor was reading | Silent while auto-playing; only what the visitor searches or picks is read out |
| Site: contact form sent | The thank-you was read three times | Read once: focus moves to a "Request sent" region |
| Site: savings calculator | The starting figures were announced as the page loaded | Read out only once the visitor changes a number |

`e2e/accessibility.spec.ts` ("screen reader pass"), `e2e/online/signin-reader.online.spec.ts` and `e2e/site.spec.ts` guard these.

Orca quirk, not a site bug: with this Chromium, Orca's arrow-key reading skips text boxes on every page, even a bare test page. Tab and the landmark key reach them.

### Needs a person on VoiceOver (and TalkBack)

These can't be run in the cloud: VoiceOver only runs on Apple devices, and phone gestures need a phone. About 30 minutes on an iPhone with VoiceOver on (Settings > Accessibility > VoiceOver), ideally also a Mac with Safari and a Windows PC with NVDA (free):

1. **Public map link on an iPhone.** Swipe right through the page: map name, list button, search, floors. Is the map picture announced as "Map of Floor 1…"?
2. **Search.** Double-tap the search box, type a space number. After a pause, does VoiceOver say how many results? Swipe to a result, double-tap: does it say the space and floor?
3. **Directions.** Double-tap Directions, pick a start. Is the distance and time read out? Swipe through the steps.
4. **Floor buttons.** Double-tap Floor 2: does it say "Floor 2 shown"?
5. **List view.** Open the list button, use the rotor (two-finger twist) set to Headings to jump between rows.
6. **Close the card.** Use the two-finger "scrub" (Z shape) to back out: does the card close? (The app's Escape key does this on a keyboard; scrub may not trigger it.)
7. **QR "You are here" link.** Open one from the camera: is "You are here" read with the place?
8. **Sign-in email.** Enter an email and send: is "Check your email" read? Then open the email in the Mail app and check the link is read as a link.
9. **bergeronmaps.com.** Swipe through the home page while the demos play: VoiceOver should stay quiet about them. Fill in the contact form with a missing name: is the error read? Send: is "Request sent" read?
10. **Text size.** Settings > Accessibility > Display & Text Size > Larger Text, at the largest size: do the viewer buttons and panel text still fit?

On NVDA (Windows), repeat 2 to 4 and 9 with the keyboard: NVDA and Orca both read the same Chromium accessibility tree, so differences there would be surprising, but NVDA is what most school IT staff test with.
